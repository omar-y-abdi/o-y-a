### Migration design still to resolve

The operation must derive canonical studio text from the exact pinned raw revision, retain version/history/public output and refresh a stale build key without a normal heavyweight first Save. The existing converter intentionally applies owner frame/CSS decisions to the studio representation and may expose conflicts; the CPU operation must not silently publish those decisions. Merely rejecting all legacy cases would leave the original first-load CPU problem unresolved.

The old uncommitted HTTP migration design is not approved for reuse. A compressed-source hash pins source bytes but does not, by itself, prove that separately submitted canonical metadata is the correct transformation of those bytes. For example, accepted page HTML plus a changed title can pass target validation while the cached studio copy and unchanged public metadata diverge. The new design needs a concrete source-to-result proof, not only artifact integrity and sanitizer success.

One candidate is trusted owner-local preparation/validation against the matching built code, followed by bounded D1 staging and one guarded commit. That avoids charging complete gzip decoding/conversion to an ordinary Worker request and can retain the exact normalized studio representation while leaving public rows untouched. The official [D1 REST query contract](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/) supports a parameterized batch object; the [Worker D1 batch contract](https://developers.cloudflare.com/d1/worker-api/d1-database/) documents transaction rollback. REST atomicity, bounded staging/retries, exact source/CAS checks, matching deployed-build identity and interrupted-operation recovery still need a concrete design and real-D1 tests before this candidate is chosen. A constrained HTTP approach remains another option if it can independently prove all relevant source-derived fields. No account credentials, production reads/writes or protocol decision are implied by this design note.
